# 架构、实现证据与扩展指南

本文描述学序当前实现的模块边界、数据流和后续扩展方式。功能规则以[需求文档](需求文档.md)为准，请求与响应以[接口文档](接口文档.md)为准。

## 一次请求如何流转

```text
React 页面 → v2/client.ts → /api 代理 → Controller
                                   → Security / CurrentUser
                                   → Service（校验、授权、事务）
                                   → Mapper / SQL → MySQL
```

`frontend/src/main.tsx` 加载 `v2/WorkspaceApp.tsx`。Vite 开发服务器将 `/api/*` 转发给 Spring Boot；生产容器使用 `frontend/nginx.conf` 完成同样的转发。`v2/client.ts` 统一处理令牌、超时和 `{code,msg,data}` 响应。浏览器本地仅保存登录会话及显示偏好，业务记录写入 MySQL。

## 数据和一致性

数据库包含学生、班级、课程、选课、考试、成绩、点名表与明细、账户、教师课程授权和操作审计，共 11 张业务表。`V1__workspace_baseline.sql` 建立基线；`V2__academic_workspace.sql` 增加独立选课与考试等结构。迁移历史由 Flyway 管理，后续改表须新增版本文件。

- 选课：Service 在事务中锁定课程行并核对容量，避免最后名额被重复占用。
- 成绩与点名：请求携带版本，更新时使用版本条件；陈旧版本返回冲突。
- 批量写入：先校验完整输入，再在事务中写入，避免部分成功。
- 权限：教师只能处理获授权课程；学生门户只读或修改本人允许的数据；前端隐藏菜单不能替代后端校验。
- 审计：记录写操作的动作、结果和必要的版本摘要，不复制密码、令牌或完整个人资料。

目前核心关系没有数据库外键，引用保护依赖 Service 规则、事务和数据库现有的主键、唯一键与检查约束。增加关联表或删除行为时，必须同时审查相关 Service 路径及并发测试；[数据库说明](../sql/README.md)列出当前表和迁移方式。

以上机制适用于当前小规模、单体服务和单个 MySQL 数据库。未使用外键不等于不存在死锁，唯一索引和 CHECK 也不替代外键的引用完整性；当前约束依赖所有写入路径共同遵守 Service 事务和锁顺序。部分课程名单与报表仍整体读取，没有据此宣称大规模查询性能或生产容量。

## 扩展一个功能

1. 在[需求文档](需求文档.md)写清角色、数据范围、输入约束、冲突与删除规则。
2. 如果需要新表或字段，增加 `V3__...sql` 等新迁移；不要修改已在环境中执行过的 V1/V2。
3. 在 Mapper 写参数化 SQL，在 Service 处理校验、授权和事务，在 Controller 暴露 API。
4. 更新[API 契约](接口文档.md)，通过 `v2/client.ts` 与对应页面接入。
5. 补充正常、无权限、冲突和回滚场景；运行前后端测试及独立数据库集成验收。

## 当前维护重点

- `AcademicService.java` 同时负责课程、选课、考试、成绩和考勤，后续可按业务边界拆分 Service，先用现有测试固定行为。
- `WorkspaceSql.java` 集中保存多组 SQL；新增复杂查询时优先按业务模块归档并保持参数绑定。
- `Assessment.tsx` 和 `Insights.tsx` 各包含多个页面；新增功能宜先抽独立组件和明确类型。
- `frontend/src/styles.css` 仍含早期界面的公共样式，正式 V2 会使用其中的基础控件样式；删改前应核对组件引用并做视觉回归。

这些是可维护性工作，不代表现有功能未实现。项目的验证范围与运行边界见[验证记录](验收记录.md)。
