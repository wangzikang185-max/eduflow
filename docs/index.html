学序 EduFlow

面向管理员、教师和学生的教务管理系统。以学生 CRUD 学习原型为起点，借助 AI 辅助开发和调试，扩展为包含身份权限、选课、考试、成绩、考勤、报表及操作审计的个人项目。

Java 21 · Spring Boot 4.0.8 · Spring Security · MyBatis · MySQL 8 · Flyway · React 19 · TypeScript

项目介绍 · 需求文档 · 接口文档 · 验证记录

功能与实现

  • 3 类角色：管理员维护业务与授权；教师只操作获授权课程；学生仅访问本人学业信息。
  • 11 张业务表：班级、学生、课程、独立选课、多次考试、成绩、点名、账户与审计。
  • JWT + BCrypt + token_version：登录、改密、禁用和退出后的令牌撤销。
  • 选课通过课程行锁及 READ COMMITTED 控制名额；成绩和点名以版本条件更新检测冲突。
  • CSV 导入和批量保存通过 Service 事务保持全成全败；学生目录使用 SQL 条件分页。
  • Flyway V1/V2 管理数据库结构；前后端分离，同源代理联调。

本地运行

准备 JDK 21、Maven 3.9、Node 22.6+、pnpm 10.11.0，以及 MySQL 8.0.16+（已验证版本 8.0.34）。

git clone https://github.com/wangzikang185-max/eduflow.git
cd eduflow
corepack enable
pnpm --dir frontend install --frozen-lockfile

创建空库（无需手动运行迁移 SQL）：

CREATE DATABASE xuexu CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

Windows 下运行 start.cmd，首次会生成并提示 runtime/local.env 后退出。填写 DB_URL、DB_USERNAME、DB_PASSWORD，保留随机生成的 JWT_SECRET 和 ADMIN_PASSWORD，然后再次运行 start.cmd。默认入口 http://127.0.0.1:5173/，管理员用户名为 admin，密码取自本机配置。项目不包含真实用户数据、数据库备份或共享默认管理员密码。

Linux/macOS 可以按 .env.example 设置环境变量，再在两个终端分别执行：

mvn -B -ntp -f backend/pom.xml spring-boot:run
pnpm --dir frontend dev

已有数据升级前先备份；Flyway 会从旧学生表 baseline 后执行迁移。MySQL DDL 不保证整段事务回滚。

版本 2.0.0 · 更新：2026-10-24。需求 · 接口 · 学习规划。

1. 项目介绍

学序是面向管理员、教师和学生的教务管理系统，使用 React/TypeScript 构建前端，以 Java 21、Spring Boot、MyBatis 和 MySQL 实现后端。系统贯通“班级维护 → 学生建档 → 开课与教师授权 → 独立选课 → 多次考试与成绩 → 课堂考勤 → 综合学业报表”，并提供学生自助门户、CSV 导入导出和服务端操作审计。

项目从学生单表 CRUD 扩展为有真实认证、数据范围控制、跨表事务和并发冲突处理的 V2。所有正式页面调用 Java HTTP 接口，业务数据写入 MySQL。旧 mock 前端保留作学习对照，正式入口不使用它。

3. 三个适合重点讲解的难点

3.1 最后一个名额的并发竞争

先查询人数、再判断、再插入不是原子操作，两个请求都可能看到还有一个名额。实现时锁定同一门课程，把容量判断和选课、空成绩初始化放进一个事务，所有修改此课程参与人数的操作遵守同一锁顺序。

真实测试中还发现：虽然已加课程行锁，事务早先读取账户建立的 REPEATABLE READ 快照仍可能让后续普通人数查询读到旧值。因此将连接隔离设为 READ COMMITTED，并在选课事务明确指定该隔离级别。修正后同时抢一个名额的两次请求结果为一个成功、一个容量不足，数据库只增加一个关联。这是两请求竞争的功能验收，不是高并发压测。

这一设计与 MySQL 官方关于事务隔离和一致性读、锁定读的说明相对应。

3.2 防止批量成绩出现部分成功或覆盖

每个成绩行有独立 version。两个人读到 version=0 后，一方保存使其变为 1；另一方继续提交 0 时，条件更新影响 0 行，后端返回 409。对一批成绩，哪怕前几条已经执行更新，只要后面一条发生版本冲突，整个事务都回滚。

前端保留失败草稿，提示重新加载后处理冲突，不自动重试覆盖他人的数据。验收特意让批量中的后一条使用旧版本，再查询数据库确认前一条也没有留下修改。

3.3 角色权限和对象范围同时控制

管理员、教师和学生不是只在前端显示不同菜单。教师查询课程、学生、成绩、考勤及报表时都带自己的授权范围；改 URL 请求另一门课程同样会被后端拒绝。学生账户以数据库 student_id 绑定身份，门户和报表按该绑定限制，不能靠请求传 studentId 看别人。

JWT 的签名和有效期由 Spring Security Resource Server 处理，密码用 BCrypt；另外通过 token_version 补上退出、改密和禁用后的即时撤销。选用成熟认证组件的依据见 Spring Security JWT 文档。

4. 核心业务和数据库设计

数据关系：班级有学生；学生和课程通过 enrollment 多对多；课程有多次 exam；每名选课学生在每次考试有一条 grade；课程每天有一张 attendance_sheet，其下是学生点名明细。user_course 只控制教师权限，不承担学生选课含义。

11 张业务表均不设置外键，保留用户此前的建模约定。Service 负责关联存在性、删除顺序、引用保护和事务；数据库仍通过主键、唯一键、索引和 CHECK 兜底。这样的设计适合学习显式业务一致性，也意味着绕过 Service 手动修改数据库可能产生孤儿记录，不能宣称没有外键仍自动级联。

3. 学生档案和班级

  • 学号去首尾空白，4–20 位字母数字短横线，数据库唯一索引以 utf8mb4_0900_ai_ci 比较；姓名去空白后 1–30 字。
  • 性别：男/女/未说明；学籍：在读/休学/已毕业。日期必须为真实 YYYY-MM-DD，年份 1000–9999。
  • 班级必须存在于班级表，专业只由该班级的 major 推导，不信任客户端 major。
  • 手机可空，非空为 1[3-9] 开头的 11 位数字；邮箱可空，非空校验格式，最多 254 字。
  • 关键词匹配姓名、学号、手机号，可组合班级与学籍。page≥1，pageSize 1–200；MySQL COUNT 与 LIMIT/OFFSET，按创建时间和 ID 倒序稳定分页。
  • 编辑必须传 version，更新成功加一；旧版本 409。body.id 不改变路径目标。
  • 班级名称和专业均 1–40 字；名称唯一。修改名称/专业时事务同步学生资料并增加学生版本；已有学生的班级不能删除。
  • 新增学生不自动选课；选课关系有单独入口。

3.1 删除

仅管理员可删除 1–500 个不重复学生 ID，存在任一无效目标时整批回滚。正常删除同时清理该学生的选课、全部考试成绩、考勤明细，禁用并解绑学生账户、撤销其旧令牌；保留课程、考试及点名表本身。页面确认框必须提示关联数据和不可恢复性。无外键场景由 Service 保证清理；不删除其他学生记录。

3.2 CSV

表头固定：学号,姓名,性别,班级,手机号,邮箱,状态,入学日期。UTF-8 可带 BOM，文件不超过 2 MiB，1–500 条数据记录；支持带引号的逗号、换行和双引号。JSON 方式上传 {csv:"..."}，JSON 请求体额外限制 16 MiB，避免转义后合法 CSV 被 2 MiB HTTP 限制截断。

Apache Commons CSV 解析后，逐条校验并报告 CSV 记录号（含表头；带引号跨行记录不等于物理文本行号）。文件内及数据库重复、非法字段/日期、错误表头/列数、坏引号均整批拒绝，异常后没有部分学生落库。文件和数据库的比较规则不同造成的唯一键冲突仍会在事务内整批回滚，返回 409。导出可选当前筛选结果或已选学生，正确转义并阻断电子表格公式；只导出有权限的数据。

4. 课程和选课

课程代码 2–20 位字母数字短横线，唯一；名称 1–40 字，教师显示名 1–50 字、教室 1–100 字；简介 0–200 字。类别为专业必修/公共基础/专业选修。学分 0.5–10、步长 0.5；课时整数 1–300；容量整数 1–10000；星期整数 1–7；时间 HH:mm–HH:mm，同一天内结束晚于开始。颜色为 orange/blue/purple/teal/pink/amber。

teacher 是显示名称；教师权限依赖独立 user_course 授权，不能靠同名判断。enrolled 从 enrollment 计数，前端不能覆盖。创建课程自动建立“课程考核”默认考试，初始权重 100；修改课程必须带 version，容量不得低于当前选课人数。

管理员一次为 1–500 个不同的在读学生选课；学生只可为本人选课。课程行 FOR UPDATE 加锁，使用 READ COMMITTED 后查询最新人数，避免旧快照导致超额。任一学生不存在、重复选课、学籍不符或容量不足则整批失败。选课同时为该课程的全部考试初始化 null 成绩；新增考试也为所有已选学生初始化成绩。

退课仅限尚无已录入成绩且没有历史考勤的关系；允许清理其空成绩后退课。课程存在选课或成绩/点名历史时拒绝删除；可删除空课程及其空考试和教师授权。删除课程和考试需要 version。

5. 考试和成绩

每课程可有多次考试。名称 1–40 字、同课程内唯一；真实日期；weight 为 0.01–100 的相对权重、最多两位小数。权重不要求加起来为 100，汇总时归一化。管理员和该课程教师可管理考试，已有非 null 成绩的考试不能删除。

每名选课学生每次考试恰有一条成绩，唯一键为 (exam_id,student_id)。score 为 null 或 0–100、最多两位小数；null 不等于 0。修改按学生提交 {studentId,score,version}，禁止重复和课程外学生；缺失 score 无效，清空使用 null。

一批最多 10000 个修改项，在同一事务中条件更新；任意输入非法、版本冲突或 SQL 失败均回滚整批。成绩页先选真实课程再加载考试，不请求固定演示 ID。班级/姓名/学号筛选和分页影响表格与导出；统计针对当前考试的全部已保存成绩，不受表格筛选影响。显示平均分、及格率、优秀人数和四级分布；未录入不进入分母。

编辑草稿在保存失败后保留；切换课程/考试、导航或关闭页面需确认。未保存修改时禁用导出和考试管理，避免导出范围与状态混淆。

6. 考勤

每课程每日一张点名表，唯一键 (course_id,attendance_date)；状态 present/late/absent/leave。首次 GET 只为当前在读且已选课学生组装预填出勤记录，savedAt=null、version=-1，不创建数据库历史。

首次保存 version=-1，之后更新带服务器 version。请求提交完整名单，不能只交筛选结果；“当前筛选全部出勤”只修改界面筛选范围，最终仍提交全部名单。重复、漏交、课程外学生和过期版本均拒绝。表头与全部明细在同一事务保存，重复保存更新原表。已保存表从历史明细读取名单，即使学生后来休学/毕业也保留；学生被明确关联删除属于第 3.1 节的例外。

没有保存过不能导出或计入统计；有草稿禁止导出，离开需确认，保存失败保留草稿。

8. 数据结构、事务与审计

11 张业务表：student、class、course、enrollment、exam、grade、attendance_sheet、attendance_record、user、user_course、operation_log；另有 flyway_schema_history。沿用 eduflow_ 前缀，均不设外键。

V1 迁移创建原 8 表；V2 新增班级、选课、考试及版本字段。已有学生 ID/资料保留；已有课程成绩迁到默认考试；只把已存在的成绩/点名关联转成选课，不为全部学生隐式选课。Flyway 为旧非空库登记 baseline 0 后顺序升级，仅执行一次。升级前备份，禁止在已有 V2 库反复手动执行 ALTER。

Service 使用事务处理班级同步、选课/退课、CSV、成绩、删除和点名。课程行锁先于学生行锁；version 条件更新负责拒绝陈旧编辑，事务隔离使用 READ COMMITTED。唯一索引负责最终冲突兜底，CHECK 约束负责合法数值和枚举。

审计记录写操作的 HTTP 结果、真实 operator_id、动作、目标和时间。学生/课程/班级/账户的单目标更新、删除记录存在性及版本前后摘要，不复制姓名、手机号、密码或 Token；批量写入记录动作及结果摘要，不宣称拥有逐单元格的成绩变更历史。失败审计通过 REQUIRES_NEW 在业务回滚后保存。Spring Security 过滤链拒绝、413 等未进入控制器的请求不属于业务审计表覆盖范围。

1. 调用约定

开发浏览器地址 127.0.0.1:5173，通过 /api 代理；后端默认 127.0.0.1:8081，路径不带 /api。生产 Nginx 或本地静态产物服务器同样提供 /api。以 GET /students 表示后端路径。

除 POST /auth/login 和 GET /health，所有接口需要 Authorization: Bearer <token>。JSON 写请求使用 application/json。ID 为字符串，新增时服务端生成 UUID，兼容旧学生 ID；日期 YYYY-MM-DD；时间为学校本地日期时间，不宣称带 UTC 偏移。

所有业务返回 JSON，包含 code、msg、data；成功 code=1，失败 code=0；不返回空 204。

{"code":1,"msg":"success","data":{"items":[],"total":0,"page":1,"pageSize":10}}

{"code":0,"msg":"数据已被修改，请重新加载后再提交","data":null}
HTTP 含义
200 成功，包括创建、更新、删除
400 参数、字段、名单或业务规则不合法
401 未登录、签名/时间/账户状态无效或已撤销

{"courseId":"course-id","examId":"exam-id","scores":[{"studentId":"student-id","score":0,"version":0},{"studentId":"another-student-id","score":null,"version":0}]}

展示数据核对 SQL（只读）

-- Read-only checks for the V2 showcase data. Execute on the normal 3306/xuexu database.
USE xuexu;

SELECT '学生' AS 数据, COUNT(*) AS 数量 FROM eduflow_student
UNION ALL SELECT '班级', COUNT(*) FROM eduflow_class
UNION ALL SELECT '课程', COUNT(*) FROM eduflow_course
UNION ALL SELECT '选课', COUNT(*) FROM eduflow_enrollment
UNION ALL SELECT '考试', COUNT(*) FROM eduflow_exam
UNION ALL SELECT '成绩（含未录入）', COUNT(*) FROM eduflow_grade
UNION ALL SELECT '已录入成绩', COUNT(*) FROM eduflow_grade WHERE score IS NOT NULL
UNION ALL SELECT '考勤表', COUNT(*) FROM eduflow_attendance_sheet
UNION ALL SELECT '考勤明细', COUNT(*) FROM eduflow_attendance_record;

SELECT student_no, name, class_name, status
FROM eduflow_student WHERE student_no LIKE 'DEMO26%' ORDER BY student_no;

SELECT c.code, c.name, c.capacity, COUNT(e.student_id) AS enrolled
FROM eduflow_course c LEFT JOIN eduflow_enrollment e ON e.course_id = c.id
GROUP BY c.id ORDER BY c.code;

SELECT status, COUNT(*) AS count FROM eduflow_attendance_record GROUP BY status;

SELECT COUNT(*) AS orphan_enrollments
FROM eduflow_enrollment e
LEFT JOIN eduflow_student s ON s.id = e.student_id
LEFT JOIN eduflow_course c ON c.id = e.course_id
WHERE s.id IS NULL OR c.id IS NULL;

SELECT COUNT(*) AS orphan_grades
FROM eduflow_grade g
LEFT JOIN eduflow_student s ON s.id = g.student_id
LEFT JOIN eduflow_exam x ON x.id = g.exam_id
WHERE s.id IS NULL OR x.id IS NULL OR x.course_id <> g.course_id;

SELECT COUNT(*) AS orphan_attendance
FROM eduflow_attendance_record r
LEFT JOIN eduflow_student s ON s.id = r.student_id
LEFT JOIN eduflow_attendance_sheet a ON a.id = r.sheet_id
WHERE s.id IS NULL OR a.id IS NULL;

  5. 预期 13 组通过、退出码 0，runtime/acceptance.json 中 passed=true。随后在隔离前端核对三类角色、实际保存与重启后的持久化。
